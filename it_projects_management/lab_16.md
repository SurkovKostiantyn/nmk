# Лабораторна робота №16 (2 години)

**Тема:** Застосування штучного інтелекту в управлінні IT-проєктом та фінальне закриття

Практика використання технологій генеративного штучного інтелекту (GenAI) у роботі Project Manager: автоматизація створення аналітичних звітів, стрес-тестування вимог за допомогою LLM, проведення фінальної ретроспективи (Lessons Learned / Post-Mortem) та складання офіційного звіту про закриття IT-проєкту (Project Closure Report).

**Мета:** Навчитися використовувати штучний інтелект як персонального Co-pilot для автоматизації рутинного документообігу, критично аналізувати згенеровані результати на безпеку та галюцинації, а також завершити життєвий цикл навчального проєкту відповідно до міжнародних стандартів PMBOK.

**Технологічний стек:** Будь-яка LLM-система (ChatGPT / Claude / Gemini / Copilot) + Google Docs / MS Word (для підсумкового звіту).

---

## Завдання

Ви дійшли до фіналу навчальної дисципліни "Управління IT-проєктами". Ваш навчальний проєкт пройшов усі фази: від первинного Статуту (Лаб №1), вибору методології (Лаб №2), моделювання процесів (Лаб №3, 4), декомпозиції вимог (Лаб №5, 6), планування часу і бюджету (Лаб №7, 8, 9) до масштабування та продуктового аналізу (Лаб №14, 15).

У цій фінальній роботі ви автоматизуєте аналітичні завдання за допомогою ШІ та проведете формальне закриття вашого проєкту.

### Перелік завдань:

1. Скласти та протестувати 2 професійні промпти для LLM (автоматизація щотижневого статус-звіту та стрес-тест ризиків безпеки).
2. Провести аудит згенерованих відповідей ШІ з точки зору галюцинацій та комплаєнсу конфіденційності (NDA).
3. Провести фінальну ретроспективу проєкту (Lessons Learned за форматом 4Ls: Liked, Learned, Lacked, Longed For).
4. Оформити підсумковий звіт про закриття проєкту (Project Closure Report) для захисту курсу.

## Хід виконання роботи

### Крок 1. Prompt Engineering для автоматизації проєктного менеджменту

Для отримання якісного результату від LLM необхідно використовувати техніку рольового контекстного промптингу (Role-Task-Context-Constraints):

#### Завдання 1.1: Генерація Executive Status Report
Складіть промпт, який передає моделі сирі дані вашого проєкту (кількість закритих задач, відхилення за часом, поточні блокери) та вимагає сформувати стислий звіт для топ-менеджменту:
- *Приклад структури промпту:*
  > "Дій як Senior Project Manager в IT-компанії. Нижче наведено сирі дані за останній спринт проєкту [Назва]: [Вставити 4-5 фактів]. Склади професійний Weekly Status Report для СТО компанії за структурою: 1) Executive Summary (2 речення); 2) Ключові досягнення; 3) Червоні прапорці та ризики; 4) Необхідні рішення від керівництва. Стиль: діловий, лаконічний, без води".

#### Завдання 1.2: Стрес-тестування вимог на ризики та Edge Cases
Складіть промпт, який бере одну з ваших User Stories з Лабораторної №5 та просить ШІ знайти 5 прихованих вразливостей, технічних ризиків або нетипових сценаріїв поведінки користувача (Edge Cases), які розробники зазвичай забувають врахувати.

_Вставте у звіт текст обох складених промптів та отримані відповіді від моделі._

### Крок 2. Критичний аналіз та аудит безпеки (NDA Check)

Проаналізуйте результат, отриманий від штучного інтелекту:
1. **Виявлення галюцинацій:** чи не запропонував ШІ застарілі технології, неіснуючі бібліотеки або нереалістичні строки?
2. **Аудит безпеки та конфіденційності (NDA):** чи містив ваш промпт реальні персональні дані (PII), реальні паролі або комерційну таємницю? Опишіть 3 правила, яких повинна дотримуватися IT-команда, щоб уникнути витоку коду при використанні AI-асистентів.

### Крок 3. Проведення ретроспективи проєкту (Lessons Learned за методом 4Ls)

Ретроспектива після завершення всього проєкту (Project Post-Mortem) дозволяє зберегти набутий досвід для майбутніх команд компанії.

Заповніть матрицю 4Ls на основі всього вашого досвіду виконання лабораторних робіт з цього курсу:

| Категорія 4Ls | Що саме відбулося під час роботи над навчальним проєктом? |
| :--- | :--- |
| **Liked (Що сподобалося):** | Які методології чи інструменти (Scrum, Jira, WBS, Гант) виявилися найзручнішими та чому? |
| **Learned (Чому навчилися):** | Які нові інженерні та управлінські концепції ви відкрили для себе? |
| **Lacked (Чого не вистачало):** | Яких технічних навичок, даних чи часу не вистачило для глибшого опрацювання деталей? |
| **Longed For (Чого хотілося б у майбутньому):** | Які практики ви обов'язково застосуєте у своєму реальному дипломному або комерційному IT-проєкті? |

### Крок 4. Оформлення фінального звіту про закриття (Project Closure Report)

Складіть паспорт успішного завершення вашого проєкту:
1. **Загальні відомості:** назва проєкту, автор (PM), фінальна дата завершення;
2. **Оцінка відповідності Scope:** перелік затверджених модулів, які було спроєктовано (від Статуту до релізу);
3. **Підсумковий вердикт успішності:**
   - Чи відповідає розроблений концепт початковим цілям SMART?
   - Чи вклався проєкт у заплановані межі часу та бюджету (за оцінками EVM)?
4. **Акт передачі (Handover Sign-off):** коротке формулювання про готовність продукту до передачі замовнику та розпуску команди розробників.

## Контрольні запитання

1. Які завдання проєктного менеджера вже сьогодні ефективно делегуються штучному інтелекту, а які залишаються виключною компетенцією людини?
2. Чому передача коду комерційного IT-проєкту у безкоштовні публічні чат-боти є критичним ризиком порушення NDA?
3. У чому полягає відмінність між ретроспективою спринта (Sprint Retrospective) та ретроспективою завершення проєкту (Project Post-Mortem)?
4. Які обов'язкові кроки включає фаза адміністративного закриття проєкту згідно зі стандартом PMBOK?
