# Лабораторна робота №14 (2 години)

**Тема:** Управління продуктом: побудова Lean Canvas та валідація MVP

Практика продуктового мислення (Product-Centric mindset): перехід від простого кодування функцій до перевірки ринкової цінності продукту, формування бізнес-моделі за шаблоном Lean Canvas, проєктування експериментів MVP (Minimum Viable Product) та розрахунок базових метрик Unit-економіки (CAC, LTV, LTV/CAC).

**Мета:** Навчитися мислити як Product Manager: визначати ключові болі цільової аудиторії, формулювати унікальну ціннісну пропозицію (UVP), проєктувати дешеві експерименти для перевірки попиту без написання важкого коду та розраховувати окупність залучення клієнтів.

**Технологічний стек:** Miro / Leanbe / Canva / Notion (для побудови Lean Canvas) + Google Sheets / Excel (для розрахунку Unit-економіки).

---

## Завдання

Ви продовжуєте розвивати свій навчальний IT-проєкт, але тепер у ролі **Product Manager (PdM)**. Ваша мета — переконатися, що створена інженерною командою система не просто працює без багів, а має ринковий попит, знайде свою цільову аудиторію та буде економічно вигідною для бізнесу.

### Перелік завдань:

1. Скласти повну бізнес-модель проєкту за шаблоном Lean Canvas (9 блоків).
2. Спроєктувати дизайн експерименту MVP (Minimum Viable Product) без повномасштабної розробки для перевірки попиту (Smoke Test / Fake Door або Wizard of Oz).
3. Розрахувати Unit-економіку проєкту (CAC, LTV, коефіцієнт LTV/CAC) та визначити North Star Metric (метрику полярної зірки).

## Хід виконання роботи

### Крок 1. Побудова моделі Lean Canvas

Lean Canvas — це лаконічний односторінковий документ, що дозволяє структурувати бізнес-модель технологічного продукту та сфокусуватися на створенні цінності для клієнта.

Заповніть усі 9 блоків матриці Lean Canvas для вашого проєкту у вигляді таблиці у звіті (або вставте експортовану схему з Miro):

| Блок Lean Canvas | Опис для вашого проєкту |
| :--- | :--- |
| **1. Problem (Проблема):** | Топ-3 головні проблеми користувача (Чому існуючі рішення не влаштовують?) |
| **2. Customer Segments (Сегменти):** | Хто цільова аудиторія? Хто є Early Adopters (першими послідовниками)? |
| **3. Unique Value Proposition:** | Єдине чітке повідомлення: яку проблему ми вирішуємо та чому ми кращі за конкурентів? |
| **4. Solution (Рішення):** | Топ-3 ключові можливості продукту, які безпосередньо усувають проблеми з блоку 1 |
| **5. Channels (Канали):** | Як саме перші користувачі дізнаються про додаток (SEO, реклама в соцмережах, реферали)? |
| **6. Revenue Streams (Доходи):** | Модель монетизації (підписка SaaS, Freemium, комісія з транзакцій, платна ліцензія) |
| **7. Cost Structure (Витрати):** | Основні статті витрат (зарплати команди, сервери AWS, маркетинг, підтримка) |
| **8. Key Metrics (Ключові метрики):** | Метрики AARRR (кількість реєстрацій, конверсія в покупку, коефіцієнт утримання Retention) |
| **9. Unfair Advantage:** | Що конкуренти не можуть легко скопіювати чи купити (унікальні алгоритми, експертиза, партнерства)? |

### Крок 2. Проєктування експерименту MVP

Перш ніж інвестувати 3 місяці роботи команди розробників у новий функціонал, необхідно перевірити гіпотезу про те, чи готові користувачі платити за це рішення.

Оберіть один із типів швидких перевірочних MVP:

- **Варіант А. "Димовий тест" (Fake Door / Smoke Test):** лендінг із презентацією фічі та кнопкою "Оформити передзамовлення" / "Спробувати Premium".
- **Варіант Б. "Чарівник країни Оз" (Wizard of Oz):** створення інтерфейсу, де складні інтеграції (наприклад, AI-підбір турів або розрахунок маршруту) спочатку виконуються оператором вручну.
- **Варіант В. Консьєрж-MVP (Concierge):** надання сервісу першим 10 клієнтам персонально у форматі консультації.

Опишіть ваш експеримент:
1. **Гіпотеза експерименту:** *"Ми віримо, що якщо покажемо [X], то користувачі зроблять [Y], тому що [Z]"*;
2. **Метрика успіху (Success Criteria):** який відсоток конверсії підтвердить гіпотезу (наприклад: "Не менше 10% відвідувачів залишать свій email та натиснуть кнопку оплати");
3. **План дій:** опис макета екрана, який побачить користувач при спробі скористатися сервісом.

### Крок 3. Розрахунок показників Unit-економіки та North Star Metric

Уявіть, що за результатами запуску пілотної версії вашого продукту ви отримали такі маркетингові та фінансові метрики:
- Витрати на рекламу (Ad Spend): **$3 000**;
- Кількість відвідувачів лендінгу: **5 000 осіб**;
- Кількість реєстрацій: **500 осіб** (конверсія 10%);
- Кількість платних підписників: **100 осіб** (конверсія з реєстрації в оплату 20%);
- Вартість щомісячної підписки (ARPU): **$25/місяць**;
- Середня тривалість життя клієнта (Lifetime): **6 місяців**.

Розрахуйте у звіті:
1. **CAC (Customer Acquisition Cost):** вартість залучення одного платного клієнта;
2. **LTV (Lifetime Value):** сукупний дохід від одного клієнта;
3. **Співвідношення LTV / CAC:** чи є бізнес-модель стійкою (перевірте правило LTV/CAC ≥ 3);
4. **Сформулюйте North Star Metric (Полярну зірку):** одну головну метрику вашого продукту, яка відображає цінність для клієнта.
