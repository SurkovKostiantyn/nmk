#### 1.2 Термінал та CLI (Command Line Interface)

Робота сучасного інженера-програміста та веброзробника не обмежується графічним інтерфейсом редактора коду. Більшість професійних інструментів — системи контролю версій (Git), пакетні менеджери (npm, Composer, pip), компілятори, лінтери, засоби збірки (Webpack, Vite) та хмарні сервіси (Docker, AWS CLI) — керуються через введення текстових інструкцій у терміналі. 

Вільне володіння інтерфейсом командного рядка є фундаментальною навичкою для будь-якого розробника.

---

##### 1.2.1 Вступ до командного рядка: PowerShell (Windows) / Bash (Linux/macOS)

**CLI (Command Line Interface)** — це текстовий інтерфейс користувача для безпосередньої взаємодії з ядром операційної системи та виконання програм. 

На відміну від графічного інтерфейсу (GUI — Graphical User Interface), де користувач взаємодіє мишкою з вікнами та кнопками:
- CLI споживає мінімальну кількість системних ресурсів;
- дозволяє автоматизувати повторювані рутинні задачі за допомогою скриптів;
- забезпечує повний контроль над параметрами запуску програм за допомогою аргументів і прапорців (flags);
- є єдиним доступним способом адміністрування віддалених серверів через захищені SSH-протоколи.

У різних операційних системах застосовуються різні командні оболонки (Shell):

- **Bash (Bourne Again Shell) / Zsh:** традиційний стандарт операційних систем сімейства Unix (Linux та macOS). Переважна більшість вебсерверів у світі працюють під управлінням дистрибутивів Linux (Ubuntu, Debian, Alpine), тому базове розуміння філософії *Unix-way* є обов'язковим для кожного веброзробника.
- **PowerShell (Windows):** об'єктно-орієнтована командна оболонка нового покоління від Microsoft. На відміну від Unix-оболонок, де результат виконання команди передається як потік звичайного тексту, у PowerShell дані передаються між командами у вигляді типізованих .NET-об'єктів. Для зручності розробників PowerShell містить безліч вбудованих аліасів (псевдонімів), що дозволяють виконувати звичні команди Unix (`ls`, `clear`, `curl`, `rm`) безпосередньо у середовищі Windows.

---

##### 1.2.2 Навігація файловою системою (команди `cd`, `ls`/`dir`, `pwd`, `mkdir`, `rm`, `cp`, `mv`)

Кожна команда в терміналі завжди виконується відносно **поточної робочої директорії** (Current Working Directory). 

Розрізняють два типи шляхів до файлів і папок:
- **Абсолютний шлях:** повний шлях від кореневого каталогу системи (наприклад, `C:\Users\Student\projects\my-app` на Windows або `/home/student/projects/my-app` у Linux).
- **Відносний шлях:** шлях відносно каталогу, у якому ви перебуваєте зараз. Поточна папка позначається як `.`, батьківська папка (на один рівень вище) — як `..`, а домашній каталог поточного користувача — як `~`.

###### Базові команди навігації та управління файлами

**1. Визначення поточної директорії (`pwd`)**

Команда `pwd` (Print Working Directory) виводить абсолютний шлях до папки, де ви зараз перебуваєте.

```bash
$ pwd
/c/Users/Student/projects
```

**2. Перегляд вмісту папки (`ls` / `dir`)**

- `ls` — виводить список файлів і підкаталогів поточної папки;
- `ls -l` — детальний вивід (права доступу, розмір файлу, дата модифікації);
- `ls -a` — відображення прихованих файлів (файли, що починаються з крапки, наприклад `.gitignore`, `.env`);
- `ls -la` — поєднання докладного виводу з показом усіх прихованих файлів.

*Приклад виконання команди `ls -la` у терміналі Git Bash:*

```bash
$ ls -la
total 24
drwxr-xr-x 1 Student 197121    0 Oct 14 12:00 .
drwxr-xr-x 1 Student 197121    0 Oct 14 11:30 ..
-rw-r--r-- 1 Student 197121   45 Oct 14 12:01 .gitignore
drwxr-xr-x 1 Student 197121    0 Oct 14 12:02 css
-rw-r--r-- 1 Student 197121 1420 Oct 14 12:05 index.html
-rw-r--r-- 1 Student 197121  850 Oct 14 12:03 README.md
```

*Приклад виконання аналогічної операції в PowerShell:*

```powershell
PS C:\Users\Student\projects\my-app> Get-ChildItem -Force

    Directory: C:\Users\Student\projects\my-app

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
d-----        14.10.2026     12:02                css
-a-h--        14.10.2026     12:01             45 .gitignore
-a----        14.10.2026     12:05           1420 index.html
-a----        14.10.2026     12:03            850 README.md
```

**3. Зміна поточної директорії (`cd`)**

- `cd <назва_папки>` — перейти всередину каталогу;
- `cd ..` — піднятися на один рівень вище;
- `cd ../..` — піднятися на два рівні вище;
- `cd ~` — перейти у домашню папку поточного користувача;
- `cd -` — повернутися у попередню директорію, де ви перебували до останнього переходу.

```bash
$ cd my-app
$ pwd
/c/Users/Student/projects/my-app

$ cd ..
$ pwd
/c/Users/Student/projects
```

**4. Створення папок (`mkdir`) та файлів (`touch` / `New-Item`)**

- `mkdir <назва>` — створити новий каталог;
- `mkdir -p pages/about/team` — створити повний ланцюг вкладених папок за одну операцію;
- `touch index.html script.js` (Unix) — створити один або кілька порожніх файлів;
- `New-Item index.html` (PowerShell) — створити новий файл у Windows.

```bash
$ mkdir -p src/controllers
$ touch src/controllers/TaskController.php
$ ls -R src
src:
controllers

src/controllers:
TaskController.php
```

**5. Копіювання (`cp`) та переміщення/перейменування (`mv`)**

- `cp file.txt backup.txt` — створити копію файлу `file.txt` з новим ім'ям;
- `cp -r assets/ assets-backup/` — рекурсивно скопіювати всю папку разом із її вмістом;
- `mv old_name.txt new_name.txt` — перейменувати файл;
- `mv script.js js/` — перемістити файл `script.js` у папку `js/`.

**6. Видалення файлів та папок (`rm`)**

- `rm file.txt` — видалити конкретний файл;
- `rm -r temp_folder/` — рекурсивно видалити каталог з усіма його вкладеними файлами та папками;
- `rm -rf build/` — рекурсивне видалення з примусовим ігноруванням запитів на підтвердження (force).

> **Увага:** Файли, видалені через термінальну команду `rm`, **не потрапляють у Кошик операційної системи (Recycle Bin)** і видаляються з диска назавжди. Будьте уважні, особливо під час використання прапорця `-rf`.

**7. Швидкий перегляд вмісту текстових файлів (`cat`, `head`, `tail`)**

- `cat .env.example` — вивести повний вміст файлу прямо в консоль;
- `head -n 10 file.txt` — вивести перші 10 рядків файлу;
- `tail -n 20 error.log` — вивести останні 20 рядків файлу (часто використовується для перевірки серверних логів);
- `tail -f app.log` — стежити за оновленнями лог-файлу в режимі реального часу.

**8. Конвеєризація (Piping) та перенаправлення потоків (`|`, `>`, `>>`)**

- `>` — перенаправити консольне виведення команди у файл (із перезаписом файлу):
  ```bash
  echo "APP_ENV=development" > .env
  ```
- `>>` — перенаправити виведення та додати його в кінець файлу (без перезапису):
  ```bash
  echo "DB_PORT=3306" >> .env
  ```
- `|` (Pipe) — передати вивід однієї команди як вхідні дані для наступної. Наприклад, знайти всі входження слова `error` у логах:
  ```bash
  cat app.log | grep "ERROR"
  ```

##### 1.2.3 Запуск адміністративних скриптів та обробка помилок терміналу

У процесі роботи кожен розробник стикається з помилками виконання команд. Нижче розглянуто типові проблеми та алгоритми їх усунення.

###### 1. Помилка «Command Not Found» (або «не є внутрішньою чи зовнішньою командою»)

*Зразок повідомлення в терміналі:*

```bash
$ composer --version
bash: composer: command not found
```

*Або у вікні командного рядка Windows:*

```text
'composer' is not recognized as an internal or external command, operable program or batch file.
```

**Причина:** Операційна система не знає, де шукати виконуваний файл програми. 

Шляхи до системних програм зберігаються у глобальній змінній середовища **`PATH`**. Якщо шлях до каталогу з програмою (наприклад, `C:\Program Files\Git\bin` або `C:\ProgramData\ComposerSetup\bin`) не внесено у `PATH`, програма запуститься лише у тому разі, якщо ви явно вкажете повний абсолютний шлях до її `.exe` файлу.

**Як діагностувати:**
- У Bash виконайте команду перевірки наявності програми: `which composer`;
- У PowerShell або cmd виконайте: `where.exe composer`;
- Перегляньте значення змінної оточення: `echo $PATH` (у Bash) або `$env:Path` (у PowerShell).

**Вирішення:** Під час встановлення розробницьких пакетів (Node.js, Git, PHP, Composer) завжди відмічайте чекбокс **"Add to PATH"**. Якщо програма вже встановлена, відкрийте *Параметри Windows → Властивості системи → Змінні середовища*, знайдіть у списку змінну `Path`, натисніть *Змінити* та додайте повний шлях до каталогу з виконуваним файлом.

###### 2. Помилка політики виконання скриптів у PowerShell (ExecutionPolicy)

*Зразок повідомлення в PowerShell:*

```powershell
PS C:\Projects\web-app> .\setup.ps1
.\setup.ps1 : File C:\Projects\web-app\setup.ps1 cannot be loaded because running scripts 
is disabled on this system. For more information, see about_Execution_Policies at 
https:/go.microsoft.com/fwlink/?LinkID=135170.
At line:1 char:1
+ .\setup.ps1
+ ~~~~~~~~~~~
    + CategoryInfo          : SecurityError: (:) [], PSSecurityException
    + FullyQualifiedErrorId : UnauthorizedAccess
```

**Причина:** За замовчуванням операційна система Windows із міркувань безпеки забороняє виконання сторонніх `.ps1` сценаріїв, якщо політика безпеки перебуває у стані `Restricted`.

**Вирішення:** Дозволити запуск локально створених скриптів та перевірених файлів для поточного користувача. Для цього у вікні PowerShell виконайте:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Після підтвердження вибору (натисніть `Y`) запуск користувацьких скриптів і віртуальних середовищ буде розблоковано.

###### 3. Помилка зайнятого мережевого порту (Port Already in Use / EADDRINUSE)

*Зразок повідомлення під час запуску локального сервера:*

```text
Error: listen EADDRINUSE: address already in use :::3000
    at Server.setupListenHandle [as _listen2] (node:net:1855:16)
    at listenInCluster (node:net:1903:12)
    at Server.listen (node:net:2001:7)
Emitted 'error' event on Server instance at:
```

**Причина:** Сервер намагається відкрити мережевий порт (наприклад, `3000` або `8000`), але цей порт уже зайнятий іншим процесом (наприклад, раніше запущеним у фоні екземпляром сервера або іншим застосунком).

**Алгоритм вирішення:**

1. **Знайти PID (Process ID) процесу, що слухає порт:**
   - На Windows (PowerShell/cmd):
     ```cmd
     netstat -ano | findstr :3000
     ```
     *Приклад відповіді:*
     ```text
       TCP    0.0.0.0:3000           0.0.0.0:0              LISTENING       14820
     ```
     Останнє число (`14820`) — це ідентифікатор процесу (PID).

   - На Linux / macOS (Bash):
     ```bash
     lsof -i :3000
     ```
     *Приклад відповіді:*
     ```text
     COMMAND   PID    USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
     node    14820 student   23u  IPv6 123456      0t0  TCP *:3000 (LISTEN)
     ```

2. **Примусово зупинити (вбити) завислий процес за його PID:**
   - На Windows:
     ```cmd
     taskkill /PID 14820 /F
     ```
     *Відповідь:* `SUCCESS: The process with PID 14820 has been terminated.`
   - На Linux / macOS:
     ```bash
     kill -9 14820
     ```

###### 4. Як зупинити нескінченний процес або завислий сервер

Якщо локальний сервер працює у терміналі в інтерактивному режимі, або ви випадково запустили скрипт із нескінченним циклом:
- Поставте курсор у вікно терміналу та натисніть комбінацію **`Ctrl + C`**. Термінал надішле сигнал переривання `SIGINT`, і виконання скрипта припиниться.
- Якщо програма очікує кінець потоку введення (EOF), натисніть **`Ctrl + D`**.
- Щоб очистити вікно консолі від накопиченого тексту, натисніть **`Ctrl + L`** або введіть команду `clear` (`cls` у Windows).

##### 1.2.4 Використання Git Bash

Оскільки сучасна веброзробка глибоко спирається на стандарти оточення Linux, користувачі Windows часто зустрічаються з несумісністю Unix-команд у стандартній командній стрічці `cmd.exe`. 

**Git Bash** — це пакетне середовище для Windows, яке включає емулятор терміналу MinTTY та оболонку Bash, збагачену повноцінним набором утиліт стандарту POSIX (GNU coreutils).

###### Чому Git Bash є рекомендованим терміналом для початківців на Windows:
- надає єдиний синтаксис команд (`ls -la`, `rm -rf`, `cat`, `grep`) на будь-якому комп'ютері незалежно від ОС;
- підтримує роботу з SSH-ключами для зв'язку з GitHub «з коробки»;
- дозволяє використовувати утиліту `curl` для перевірки REST API та інспекції заголовків HTTP:
  ```bash
  $ curl -I https://api.github.com
  HTTP/2 200 
  server: GitHub.com
  content-type: application/json; charset=utf-8
  ```
- містить швидкий консольний текстовий редактор `nano` для редагування конфігурацій прямо в терміналі:
  ```bash
  nano .env
  ```

###### Налаштування Git Bash за замовчуванням у Visual Studio Code

Щоб при відкритті терміналу у VS Code (`Ctrl + ~`) одразу запускався Git Bash:

1. Натисніть комбінацію `Ctrl + Shift + P` для виклику панелі команд;
2. Почніть вводити: **`Terminal: Select Default Profile`** і натисніть `Enter`;
3. У випадаючому списку оберіть пункт **Git Bash**.

Тепер нові термінали у вашому редакторі автоматично працюватимуть у звичному середовищі Bash.

##### 1.2.5 Використання Docker та Docker Compose

У класичній розробці студенти часто стикаються з проблемою: *«На моєму комп'ютері все працювало, а на іншому — падає з помилкою»*. Причиною зазвичай є різна версія встановленого інтерпретатора (наприклад, PHP 8.1 проти PHP 8.3), інші налаштування СУБД MySQL чи відсутність системних бібліотек.

**Docker** повністю розв'язує цю проблему за допомогою **контейнеризації**. Контейнер — це стандартизований, ізольований програмний пакунок, який містить усередині сам застосунок, системні утиліти, конфігурації та всі необхідні бібліотеки для гарантованого відтворення середовища на будь-якій системі.

На відміну від важких віртуальних машин (VirtualBox чи VMware), контейнери використовують спільне ядро хостової операційної системи, завдяки чому стартують за долі секунди та споживають у рази менше оперативної пам'яті.

###### Ключові команди Docker у щоденній розробці

**1. Перевірка статусу та версії демона Docker:**

```bash
$ docker --version
Docker version 27.2.0, build 3e425e3
```

**2. Запуск контейнера (`docker run`)**

Запустимо тестовий контейнер вебсервера Nginx із прокиданням порту `8080` вашого комп'ютера на порт `80` всередині контейнера:

```bash
$ docker run -d -p 8080:80 --name my-web-server nginx:alpine
Unable to find image 'nginx:alpine' locally
alpine: Pulling from library/nginx
c158987b0551: Pull complete 
Digest: sha256:3266b42...
Status: Downloaded newer image for nginx:alpine
4d8b6c891f3a2c5123d4e6f8b9a1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9
```

Прапорці команди:
- `-d` (detached) — запуск у фоновому режимі, щоб консоль залишалася доступною для подальших команд;
- `-p 8080:80` — перенаправлення трафіку з локального порту `8080` на внутрішній порт `80` контейнера;
- `--name my-web-server` — надання зрозумілого текстового імені контейнеру.

**3. Перегляд списку активних контейнерів (`docker ps`)**

Команда `docker ps` показує всі контейнери, що працюють у цей момент.

```bash
$ docker ps
CONTAINER ID   IMAGE          COMMAND                  CREATED         STATUS         PORTS                  NAMES
4d8b6c891f3a   nginx:alpine   "/docker-entrypoint.…"   2 minutes ago   Up 2 minutes   0.0.0.0:8080->80/tcp   my-web-server
```

Якщо додати прапорець `docker ps -a`, термінал відобразить усі контейнери, включаючи зупинені.

**4. Перегляд консольних логів (`docker logs`)**

Дозволяє подивитися, що саме застосунок виводить у консоль всередині контейнера (повідомлення про запуск, помилки, запити):

```bash
$ docker logs my-web-server
/docker-entrypoint.sh: /docker-entrypoint.d/ is not empty, will attempt to perform configuration
2026/10/14 12:00:00 [notice] 1#1: using the "epoll" event method
2026/10/14 12:00:00 [notice] 1#1: nginx/1.27.0
2026/10/14 12:00:00 [notice] 1#1: start worker processes
127.0.0.1 - - [14/Oct/2026:12:01:23 +0000] "GET / HTTP/1.1" 200 615 "-" "Mozilla/5.0..."
```

Прапорець `-f` (`docker logs -f my-web-server`) вмикає режим потокового відстеження логів (follow), подібний до `tail -f`.

**5. Виконання команд усередині контейнера (`docker exec`)**

Іноді розробнику потрібно потрапити в середину контейнера (наприклад, для інспекції файлів чи перевірки бази даних):

```bash
$ docker exec -it my-web-server sh
/ # ls -l /usr/share/nginx/html/
total 8
-rw-r--r-- 1 root root 497 Jun 25 10:00 50x.html
-rw-r--r-- 1 root root 615 Jun 25 10:00 index.html
/ # exit
```

**6. Зупинка та очищення (`docker stop`, `docker rm`)**

```bash
$ docker stop my-web-server
my-web-server

$ docker rm my-web-server
my-web-server
```

###### Оркестрація за допомогою Docker Compose

Більшість сучасних вебпроєктів є багатокомпонентними: вони складаються одночасно з бекенд-сервера, бази даних MySQL, кешування Redis та поштового сервісу. Запускати кожну службу окремою довгою командою `docker run` вкрай незручно.

**Docker Compose** дозволяє описати всю архітектуру вашого проєкту в одному декларативному файлі `docker-compose.yml`.

*Приклад файлу `docker-compose.yml` для стеку PHP + MySQL:*

```yaml
version: '3.8'

services:
  web:
    image: php:8.2-apache
    ports:
      - "8000:80"
    volumes:
      - ./src:/var/www/html
    depends_on:
      - db

  db:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: rootsecretpassword
      MYSQL_DATABASE: task_manager
    ports:
      - "3306:3306"
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
```

**Основні команди Docker Compose:**

- **Підняти всю інфраструктуру у фоновому режимі:**
  ```bash
  $ docker compose up -d
  [+] Running 3/3
   ✔ Network my-app_default       Created
   ✔ Container my-app-db-1        Started
   ✔ Container my-app-web-1       Started
  ```
- **Переглянути статус запущених сервісів стеку:**
  ```bash
  $ docker compose ps
  NAME            IMAGE            COMMAND                  SERVICE   CREATED         STATUS         PORTS
  my-app-db-1     mysql:8.0        "docker-entrypoint.s…"   db        2 minutes ago   Up 2 minutes   0.0.0.0:3306->3306/tcp
  my-app-web-1    php:8.2-apache   "docker-php-entrypoi…"   web       2 minutes ago   Up 2 minutes   0.0.0.0:8000->80/tcp
  ```
- **Зупинити та видалити контейнери й мережі проєкту:**
  ```bash
  $ docker compose down
  [+] Running 3/3
   ✔ Container my-app-web-1       Removed
   ✔ Container my-app-db-1        Removed
   ✔ Network my-app_default       Removed
  ```

##### 1.2.6 WSL 2 (Windows Subsystem for Linux)

Для студентів, які використовують комп'ютери під управлінням Windows, але розробляють програми під серверні платформи Linux, компанія Microsoft спільно з Canonical створила **WSL 2 (Windows Subsystem for Linux другої версії)**.

WSL 2 — це повноцінна підсистема, що запускає реальне модифіковане ядро Linux у межах легкої віртуалізації Hyper-V безпосередньо у Windows. Вона стартує за лічені секунди, споживає ресурси динамічно (вивільняючи пам'ять назад у Windows, коли вона не використовується) і не потребує створення важких віртуальних машин чи налаштування подвійного завантаження системи (Dual Boot).

###### Чому WSL 2 критично важливий для веброзробника:
1. **Продуктивність файлової системи:** Рідна файлова система Linux (`EXT4`) обробляє операції з тисячами дрібних файлів (каталоги `node_modules`, кеші Composer чи тимчасові файли фреймворків) у 5–10 разів швидше, ніж стандартна файлова система Windows `NTFS`.
2. **100% сумісність інструментів:** Усі пакети, Bash-скрипти, утиліти компіляції та Docker працюють абсолютно ідентично до бойових серверів деплою на Ubuntu/Debian.
3. **Гібридний доступ:** Ви можете запускати програми Windows зсередини Linux і навпаки — переглядати файли Linux безпосередньо у стандартному Провіднику Windows.

###### Встановлення та керування WSL

Встановлення WSL в операційній системі Windows 10/11 виконується однією командою у вікні PowerShell, запущеному від імені Адміністратора:

```powershell
wsl --install
```

За замовчуванням ця команда завантажить останнє ядро Linux та дистрибутив **Ubuntu**. Після завершення інсталяції та перезавантаження комп'ютера система попросить вас ввести логін і пароль для користувача Linux.

**Базові команди керування WSL у PowerShell:**

- Перевірити статус та версію встановлених дистрибутивів:
  ```powershell
  PS C:\> wsl -l -v
    NAME      STATE           VERSION
  * Ubuntu    Running         2
  ```
- Запустити термінал Linux за замовчуванням:
  ```powershell
  PS C:\> wsl
  student@desktop:~$ uname -a
  Linux desktop 5.15.153.1-microsoft-standard-WSL2 #1 SMP Fri Mar 29 23:14:13 UTC 2024 x86_64 x86_64 x86_64 GNU/Linux
  ```
- Завершити роботу WSL для повного звільнення оперативної пам'яті:
  ```powershell
  wsl --shutdown
  ```

###### Взаємодія між файловими системами Windows та Linux

WSL 2 забезпечує двосторонній прозорий доступ до дисків:

- **Доступ до дисків Windows із Linux:**
  Усі логічні диски вашого ПК монтуються всередині WSL у каталозі `/mnt/`. Наприклад, диск `C:` доступний за адресою `/mnt/c/`:
  ```bash
  cd /mnt/c/Users/Student/Desktop
  ```
- **Доступ до файлів Linux із Windows:**
  Якщо ви перебуваєте в терміналі WSL і хочете відкрити поточну папку в графічному Провіднику Windows, виконайте команду:
  ```bash
  explorer.exe .
  ```
  Також ви можете в адресному рядку Провідника Windows напряму ввести мережевий шлях: `\\wsl$\Ubuntu\home\student\projects`.

> **Порада щодо максимальної швидкодії:** Завжди зберігайте вихідний код навчальних проєктів у рідній файловій системі Linux (наприклад, у домашній папці `/home/student/projects/`), а не на змонтованому диску `/mnt/c/`. Це гарантує максимальну швидкість операцій вводу/виводу під час роботи з `npm install`, збірки коду та індексації проєктів.

###### Інтеграція Visual Studio Code з WSL

Найбільш продуктивним сценарієм розробки на Windows є зв'язка VS Code та розширення **WSL** (ідентифікатор: `ms-vscode-remote.remote-wsl`):

1. Встановіть офіційне розширення **WSL** у VS Code;
2. Відкрийте термінал WSL (Ubuntu), перейдіть у каталог вашого проєкту та введіть:
   ```bash
   code .
   ```
3. VS Code автоматично завантажить невеликий серверний агент усередину WSL. Графічне вікно редактора залишатиметься рідним вікном Windows, проте всі вбудовані термінали, лінтери, інтерпретатори мов та розширення працюватимуть усередині швидкого та чистого середовища Linux.
