# Лекція №17 (2 години). Таймери та прості ефекти на чистому JavaScript

## План лекції

1. Час у вебінтерфейсі: асинхронне виконання та цикл подій.
2. Одноразове відкладене виконання: `setTimeout()` і `clearTimeout()`.
3. Повторювані дії: `setInterval()`, `clearInterval()` та повторне планування через `setTimeout()`.
4. Точність таймерів, вимірювання часу й поведінка фонової вкладки.
5. Прості ефекти: тимчасові повідомлення, CSS-переходи та `requestAnimationFrame()`.
6. Створення таймера зворотного відліку з паузою та скиданням.
7. Створення слайдера з ручним керуванням і автоматичним перемиканням.
8. Типові помилки, перевірка роботи та практичні завдання.

Орієнтовний розподіл для двох академічних годин (90 хвилин): вступ і цикл подій — 10 хв; API таймерів — 15 хв; точність часу — 10 хв; прості ефекти — 10 хв; зворотний відлік — 20 хв; слайдер — 15 хв; обговорення помилок і підбиття підсумків — 10 хв. Практичні завдання наприкінці можна використати для самостійної роботи.

## Перелік умовних скорочень

- **JS** (JavaScript) — мова програмування, яку використовуємо для поведінки вебсторінки.
- **API** (Application Programming Interface) — інтерфейс прикладного програмування.
- **HTML** (HyperText Markup Language) — мова гіпертекстової розмітки.
- **CSS** (Cascading Style Sheets) — каскадні таблиці стилів.
- **DOM** (Document Object Model) — об'єктна модель документа.
- **UI** (User Interface) — користувацький інтерфейс.
- **ID** (Identifier) — ідентифікатор; у цій лекції, зокрема, значення для скасування таймера.
- **мс** — мілісекунда; 1000 мс дорівнюють одній секунді.

## Вступ

Інтерактивна сторінка реагує не лише на натискання кнопок. Повідомлення про збереження зникає за кілька секунд, слайдер показує наступну картку, таймер відображає час до завершення вправи. У кожному випадку інтерфейс має змінитися пізніше або повторювати дію з певною періодичністю.

Для таких завдань браузер надає таймери. Вони дозволяють запланувати виклик функції, а тим часом продовжити виконання коду. Однак запис «виконати через секунду» не означає, що функція обов'язково запуститься рівно через 1000 мс. Розуміння цієї відмінності потрібне і для простого повідомлення, і для надійного відліку часу.

**Мета лекції** — навчитися керувати діями в часі засобами браузера та створювати невеликі інтерактивні компоненти без сторонніх бібліотек. Після опрацювання матеріалу студент має вміти запускати й скасовувати таймери, пояснювати порядок виконання коду, обчислювати залишок часу та пов'язувати стан компонента з DOM.

Для роботи потрібні базові знання функцій, змінних, масивів, обробників подій і методів `querySelector()` та `addEventListener()`. Короткі приклади можна виконувати в консолі браузера. Повні приклади з розділів 6 і 7 слід зберігати в **окремі HTML-файли** й відкривати у браузері: кожен із них є самостійною сторінкою.

## 1. Час у вебінтерфейсі та цикл подій

### 1.1. Таймер як запланований виклик

Розглянемо ситуацію: після натискання кнопки потрібно показати повідомлення, а через три секунди прибрати його. Якщо змусити програму активно чекати в циклі, основний потік буде зайнятий, а інтерфейс перестане нормально реагувати на дії користувача. Правильне рішення — зареєструвати функцію, яку браузер зможе викликати пізніше.

```javascript
console.log("Початок");

setTimeout(() => {
  console.log("Відкладене повідомлення");
}, 1000);

console.log("Продовження роботи");
```

Спочатку побачимо «Початок», потім «Продовження роботи», а згодом — «Відкладене повідомлення». `setTimeout()` повертає керування відразу після реєстрації таймера: наступний рядок не чекає на його завершення.

Методи таймерів у цьому занятті належать до браузерного API об'єкта `window`. Сама мова JavaScript визначає функції, числа та об'єкти, а середовище виконання надає механізм планування. Тому поведінку браузерних таймерів не слід без перевірки переносити на інші середовища, наприклад Node.js.

### 1.2. Спрощена модель виконання

Для прикладів лекції достатньо такої моделі:

1. Поточний синхронний код виконується у стеку викликів.
2. Браузер обліковує зареєстровані таймери.
3. Після спливу затримки відповідне завдання може бути поставлене в чергу на виконання.
4. Цикл подій (*event loop*) забезпечує подальше виконання завдань, коли поточна робота завершилася.

Виклик таймера не перериває довільну функцію посеред її виконання. Якщо основний потік зайнятий тривалим обчисленням, обробник таймера чекатиме. Специфікація прямо застерігає, що таймери не гарантують запуск точно за розкладом. [HTML Standard: Timers](https://html.spec.whatwg.org/multipage/timers-and-user-prompts.html#timers).

```javascript
console.log("А");
setTimeout(() => console.log("Б"), 0);
console.log("В");
// Порядок: А, В, Б.
```

Нульова затримка означає відкладене планування, а не негайний виклик. Поточний код має завершитися раніше. У браузері існують також мікрозавдання, зокрема обробники Promise; їхній докладний розгляд виходить за межі цієї лекції. Наведена модель пояснює базові приклади, але не описує всі правила планувальника.

### 1.3. Чому не можна очікувати в циклі

```javascript
// Антиприклад: не використовуйте для затримок в інтерфейсі.
const start = Date.now();
while (Date.now() - start < 3000) {
  // Основний потік зайнятий непотрібною роботою.
}
console.log("Минуло приблизно три секунди");
```

Такий код витрачає процесорний час і затримує обробку натискань та оновлення сторінки. Таймер дозволяє чекати без такого блокування. Водночас важка робота **всередині** обробника таймера теж блокує основний потік: відкладений запуск не робить саме обчислення паралельним.

## 2. Одноразова дія: setTimeout() і clearTimeout()

### 2.1. Синтаксис і функція зворотного виклику

```javascript
const timeoutId = setTimeout(callback, delay, argument1, argument2);
```

`callback` — функція зворотного виклику (*callback*), `delay` — затримка в мілісекундах. Додаткові аргументи необов'язкові й передаються цій функції. Результат у браузері — числовий ідентифікатор зареєстрованого таймера. [MDN: setTimeout()](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout).

```javascript
function greet(name) {
  console.log(`Вітаємо, ${name}!`);
}

setTimeout(greet, 1500, "Олено");

// Інший спосіб передати дані — використати замикання.
setTimeout(() => {
  greet("Андрію");
}, 2000);
```

У першому випадку передаємо посилання на `greet`. У другому — нову функцію, яка згодом викличе `greet` із потрібним аргументом.

Порівняймо два записи:

```javascript
setTimeout(greet, 1000, "Ірино"); // Правильно: передано функцію.

// Помилка: greet викликається відразу, а таймер отримує її результат.
// setTimeout(greet("Ірино"), 1000);
```

Хоча API допускає рядок із кодом, у навчальних і прикладних програмах слід передавати функцію. Це робить залежності явними й дозволяє уникнути виконання коду, сформованого як текст.

### 2.2. Скасування запланованого виклику

```javascript
const timeoutId = setTimeout(() => {
  console.log("Цей текст не з'явиться");
}, 3000);

clearTimeout(timeoutId);
```

Щоб скасувати таймер, потрібно зберегти саме його ID. `clearTimeout()` прибирає запланований виклик, але не повертає вже виконані зміни й не перериває функцію, яка вже почала працювати. [HTML Standard: Timers](https://html.spec.whatwg.org/multipage/timers-and-user-prompts.html#timers).

Для стану «таймер зараз відсутній» зручно використовувати `null`:

```javascript
let reminderId = null;

function scheduleReminder() {
  clearTimeout(reminderId);

  reminderId = setTimeout(() => {
    reminderId = null;
    console.log("Час зробити перерву");
  }, 5000);
}

scheduleReminder();
scheduleReminder(); // Попереднє нагадування скасовано; залишилося одне.
```

Скасування перед новим плануванням реалізує правило: актуальним є останній запит. Це корисно для повторних натискань кнопки й відкладених підказок.

### 2.3. Відкладений виклик методу об'єкта

Якщо метод використовує `this`, передавання його окремо може втратити потрібний об'єкт виклику. Зрозумілий для початківця спосіб — обгорнути виклик у стрілкову функцію:

```javascript
const lesson = {
  title: "Таймери",
  announce() {
    console.log(this.title);
  }
};

setTimeout(() => lesson.announce(), 1000);
// Альтернатива: setTimeout(lesson.announce.bind(lesson), 1000);
```

Тут `lesson.announce()` виконується саме як метод `lesson`, тому читає його властивість `title`.

## 3. Повторювані дії: setInterval() та повторне планування

### 3.1. Запуск і зупинка інтервалу

`setInterval()` організовує повторні виклики функції з указаною затримкою. Перший виклик також відкладений; для негайного оновлення потрібно окремо викликати функцію перед запуском інтервалу. Повторення припиняють через `clearInterval()`. [MDN: setInterval()](https://developer.mozilla.org/en-US/docs/Web/API/Window/setInterval).

```javascript
let count = 0;

const intervalId = setInterval(() => {
  count += 1;
  console.log(`Оновлення №${count}`);

  if (count === 5) {
    clearInterval(intervalId);
  }
}, 1000);
```

Цей приклад рахує **кількість викликів**, а не точно вимірює секунди. Він коректний як лічильник оновлень, але потребує іншого підходу для вимірювання часу.

### 3.2. Захист від кількох одночасних інтервалів

Якщо кожне натискання «Старт» створюватиме новий інтервал, функція почне виконуватися кілька разів за період. Компонент повинен зберігати стан запуску:

```javascript
let intervalId = null;

function update() {
  console.log("Періодичне оновлення");
}

function start() {
  if (intervalId !== null) return;
  update();
  intervalId = setInterval(update, 1000);
}

function stop() {
  clearInterval(intervalId);
  intervalId = null;
}
```

Після зупинки треба і скасувати інтервал, і повернути змінну до `null`. Сам виклик `clearInterval()` значення змінної не змінює. Якщо присвоїти лише `intervalId = null`, старий інтервал продовжить працювати, а його ID буде втрачено.

### 3.3. Повторний setTimeout()

Інший підхід — планувати наступний виклик наприкінці поточного:

```javascript
let timeoutId = null;
let running = false;

function tick() {
  if (!running) return;

  console.log("Виконуємо одну порцію роботи");
  timeoutId = setTimeout(tick, 1000);
}

function startLoop() {
  if (running) return;
  running = true;
  tick();
}

function stopLoop() {
  running = false;
  clearTimeout(timeoutId);
  timeoutId = null;
}
```

Це асинхронне повторне планування: між викликами стек звільняється. Якщо робота тривала 200 мс, наступний запуск у цьому прикладі відбудеться приблизно через 1000 мс **після її завершення**, тобто відстань між початками становитиме щонайменше приблизно 1200 мс з урахуванням планування.

Цей підхід зручний, коли потрібно змінювати затримку або чекати завершення попередньої операції. Для асинхронного запиту наступний `setTimeout()` треба ставити після завершення запиту, наприклад після `await`. Саме перенесення асинхронного виклику всередину `tick()` без очікування його результату не усуває накладання операцій. [MDN: зауваження щодо тривалості операцій в setInterval()](https://developer.mozilla.org/en-US/docs/Web/API/Window/setInterval#ensure_that_execution_duration_is_shorter_than_interval_frequency).

Синхронні обробники одного основного потоку не виконуються одночасно. Проблема накладання особливо помітна для запитів: один обробник уже завершився, але розпочатий ним запит ще триває, коли наступний обробник запускає інший.

### 3.4. Вибір механізму

| Завдання | Зручний механізм | Приклад |
| --- | --- | --- |
| Одна дія пізніше | `setTimeout()` | Прибрати повідомлення |
| Регулярне коротке оновлення | `setInterval()` | Перемалювати залишок часу |
| Пауза після завершення роботи | Повторний `setTimeout()` | Наступна перевірка після попередньої |
| Плавна зміна стилю між двома станами | CSS `transition` | Змінити прозорість панелі |
| Покадрова зміна, обчислювана в JS | `requestAnimationFrame()` | Рух за обчисленою траєкторією |

## 4. Точність таймерів і вимірювання часу

### 4.1. Запланована затримка та фактичний запуск

На момент запуску впливають зайнятість основного потоку, інші завдання та політика браузера щодо фонових сторінок. Для глибоко вкладених таймерів браузер застосовує мінімальну затримку 4 мс. Крім того, затримка обмежена діапазоном 32-бітного знакового цілого: значення понад 2 147 483 647 мс, тобто приблизно 24,8 дня, можуть оброблятися не так, як очікується. Планувати далеку дату одним великим таймером не слід. [MDN: обмеження setTimeout()](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout#reasons_for_delays_longer_than_specified).

Практичний висновок: таймер повідомляє, що настав час **перевірити стан**, але сам по собі не є точним годинником.

### 4.2. Чому віднімання одиниці накопичує похибку

Уявімо відлік на 10 секунд. Програма раз на секунду виконує `seconds -= 1`. Через навантаження третій виклик стався на дві секунди пізніше. Програма відніме лише одиницю, хоча минуло більше часу. Після кількох затримок показаний залишок відставатиме від фактичного.

Для відліку використовуємо кінцеву позначку часу:

```javascript
const durationMs = 10_000;
const deadline = Date.now() + durationMs;

function getRemainingMs() {
  return Math.max(0, deadline - Date.now());
}
```

Кожне оновлення заново обчислює різницю. Якщо між оновленнями минуло п'ять секунд, наступне відображення врахує всі п'ять секунд, а не лише один пропущений крок.

`Date.now()` повертає кількість мілісекунд від початку епохи Unix. Такий формат зручний для календарного терміну й зберігання кінцевої позначки між завантаженнями сторінки. [MDN: Date.now()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/now).

### 4.3. Date.now() і performance.now()

Для коротких вимірювань усередині поточної сторінки є `performance.now()`. Це монотонне джерело часу відносно початкової точки середовища: на відміну від системного календарного часу воно не стрибає через ручне переведення годинника. Водночас поведінка під час сну операційної системи відрізняється між реалізаціями. [MDN: performance.now()](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now).

| Потреба | Вибір |
| --- | --- |
| Показати залишок до визначеної дати | `Date.now()` та календарний deadline |
| Виміряти тривалість обчислення | `performance.now()` |
| Зберегти кінцевий термін у `localStorage` | Часова позначка на основі `Date.now()` |
| Обчислити прогрес покадрової анімації | Позначка часу з `requestAnimationFrame()` |

У навчальному відліку нижче використаємо `Date.now()`: він дозволяє наочно пояснити кінцевий термін. Якщо користувач змінить системний час, залишок теж зміниться. Для короткого інтервалу, який має бути незалежним від переведення годинника, можна замінити обидва звернення до джерела часу на `performance.now()`. Змішувати ці два види позначок в одному відніманні не можна: у них різні початкові точки.

### 4.4. Фонова вкладка

Браузер може рідше виконувати таймери прихованої вкладки. Подія `visibilitychange` й властивість `document.hidden` дають змогу реагувати на зміну видимості документа. [MDN: Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API).

Для слайдера логічно призупинити непотрібні перемикання. Для відліку до кінцевого терміну логічно продовжувати враховувати час і після повернення відразу перемалювати залишок. Це різні вимоги до поведінки, хоча обидва компоненти використовують таймери.

Якщо сторінка була призупинена або закрита, клієнтський код не гарантує виконання дії точно в момент завершення. Для навчального інтерфейсу достатньо виявити завершення під час наступного доступного оновлення.

## 5. Прості ефекти в інтерфейсі

### 5.1. Тимчасове повідомлення

Потрібно показати повідомлення після дії та приховати через три секунди. Повторне натискання має відраховувати нові три секунди. Наведений фрагмент можна вставити всередину `body`; скрипт розміщено після елементів.

```html
<button id="save" type="button">Зберегти</button>
<p id="notice" role="status" hidden>Зміни збережено.</p>

<script>
  const saveButton = document.querySelector("#save");
  const notice = document.querySelector("#notice");
  let hideId = null;

  saveButton.addEventListener("click", () => {
    clearTimeout(hideId);
    notice.hidden = false;

    hideId = setTimeout(() => {
      notice.hidden = true;
      hideId = null;
    }, 3000);
  });
</script>
```

Старий таймер скасовується **перед** створенням нового. Без цього повідомлення могло б зникнути за мить після повторного натискання, коли спрацював би попередній таймер. `role="status"` позначає повідомлення про результат дії для допоміжних технологій.

### 5.2. Плавність через CSS transition

Для зміни прозорості або положення між двома станами зазвичай достатньо CSS. JS лише перемикає клас; браузер обчислює проміжні значення.

```html
<style>
  .panel {
    padding: 1rem;
    background: #e8f0ff;
    opacity: 0;
    transform: translateY(12px);
    transition: opacity 300ms ease, transform 300ms ease;
  }

  .panel.is-visible {
    opacity: 1;
    transform: translateY(0);
  }

  @media (prefers-reduced-motion: reduce) {
    .panel { transition: none; }
  }
</style>

<button id="reveal" type="button">Показати повідомлення</button>
<p id="panel" class="panel">Готово до наступного кроку.</p>

<script>
  document.querySelector("#reveal").addEventListener("click", () => {
    document.querySelector("#panel").classList.add("is-visible");
  });
</script>
```

У цьому фрагменті приховування є лише візуальним: елемент з `opacity: 0` зберігає місце в макеті й залишається в дереві доступності. Для повноцінної приховуваної інтерактивної панелі треба також керувати її доступністю та фокусом. Тут елемент містить лише текст і демонструє перехід між двома візуальними станами.

Медіазапит `prefers-reduced-motion` дає змогу врахувати налаштування користувача щодо зменшення руху. [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion).

### 5.3. Коли потрібен requestAnimationFrame()

Не варто вважати `setInterval(..., 16)` гарантією плавних 60 кадрів за секунду. Якщо наступний стан треба обчислювати в JS для кожного кадру, використовують `requestAnimationFrame()`: він планує один виклик перед майбутнім перемальовуванням. Для продовження анімації потрібно запланувати наступний кадр. Прогрес обчислюють за переданою часовою позначкою, а не за кількістю кадрів. [MDN: requestAnimationFrame()](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame).

```html
<div id="box" style="width: 40px; height: 40px; background: teal;"></div>
<button id="move" type="button">Перемістити</button>

<script>
  const box = document.querySelector("#box");
  const moveButton = document.querySelector("#move");
  let frameId = null;

  moveButton.addEventListener("click", () => {
    cancelAnimationFrame(frameId);

    if (matchMedia("(prefers-reduced-motion: reduce)").matches) {
      box.style.transform = "translateX(200px)";
      frameId = null;
      return;
    }

    const duration = 1000;
    let startedAt = null;
    box.style.transform = "translateX(0)";

    function animate(timestamp) {
      if (startedAt === null) startedAt = timestamp;
      const progress = Math.min((timestamp - startedAt) / duration, 1);
      box.style.transform = `translateX(${200 * progress}px)`;

      if (progress < 1) {
        frameId = requestAnimationFrame(animate);
      } else {
        frameId = null;
      }
    }

    frameId = requestAnimationFrame(animate);
  });
</script>
```

Для тривалості 1000 мс прогрес змінюється від 0 до 1, а координата — від 0 до 200 пікселів. `Math.min()` обмежує кінцеве положення. Повторне натискання спочатку скасовує попередню анімацію, потім запускає нову від початку. Для такого простого руху CSS теж був би достатнім; приклад показує принцип обчислення кадру в JS.

## 6. Практичний приклад: таймер зворотного відліку

### 6.1. Вимоги та стан

Створимо відлік на одну хвилину з кнопками «Старт», «Пауза» і «Скинути». Він має виконувати такі вимоги:

- повторне натискання «Старт» не створює іншого інтервалу;
- пауза фіксує фактичний залишок у мілісекундах;
- продовження створює нову кінцеву позначку з цього залишку;
- завершення показує `00:00`, повідомляє результат і скасовує інтервал;
- скидання повертає початкову тривалість;
- затримка оновлення не перетворюється на накопичену похибку відліку.

Збережемо три основні змінні: `remainingMs` — залишок під час зупинки, `deadline` — кінцевий термін поточного запуску, `intervalId` — ID оновлення або `null`. Відображення є наслідком стану; текст `00:35` не використовується як джерело даних для обчислень.

### 6.2. Повний приклад

Збережіть код у файл `countdown.html`. Зовнішні бібліотеки й ресурси не потрібні.

```html
<!doctype html>
<html lang="uk">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Зворотний відлік</title>
  <style>
    body { font-family: system-ui, sans-serif; padding: 2rem; }
    .timer { max-width: 24rem; padding: 1.5rem; border: 1px solid #777; }
    .timer__value { font-size: 3rem; font-variant-numeric: tabular-nums; }
    button { padding: 0.6rem 1rem; margin: 0.2rem; }
    .is-finished { border-color: #087443; background: #ecfff4; }
  </style>
</head>
<body>
  <section id="timer" class="timer" aria-labelledby="timer-title">
    <h1 id="timer-title">Хвилина для вправи</h1>
    <p id="time" class="timer__value" role="timer" aria-live="off">01:00</p>
    <div>
      <button id="start" type="button">Старт</button>
      <button id="pause" type="button" disabled>Пауза</button>
      <button id="reset" type="button">Скинути</button>
    </div>
    <p id="status" role="status">Готово до запуску.</p>
  </section>

  <script>
    const INITIAL_MS = 60_000;
    const timer = document.querySelector("#timer");
    const time = document.querySelector("#time");
    const status = document.querySelector("#status");
    const startButton = document.querySelector("#start");
    const pauseButton = document.querySelector("#pause");
    const resetButton = document.querySelector("#reset");

    let remainingMs = INITIAL_MS;
    let deadline = 0;
    let intervalId = null;

    function formatTime(milliseconds) {
      const totalSeconds = Math.ceil(milliseconds / 1000);
      const minutes = Math.floor(totalSeconds / 60);
      const seconds = totalSeconds % 60;
      return `${String(minutes).padStart(2, "0")}:${String(seconds).padStart(2, "0")}`;
    }

    function render(milliseconds) {
      time.textContent = formatTime(milliseconds);
    }

    function stopUpdates() {
      clearInterval(intervalId);
      intervalId = null;
      pauseButton.disabled = true;
    }

    function finish() {
      stopUpdates();
      remainingMs = 0;
      render(remainingMs);
      startButton.disabled = true;
      timer.classList.add("is-finished");
      status.textContent = "Час вичерпано. Для нового відліку натисніть «Скинути».";
    }

    function update() {
      remainingMs = Math.max(0, deadline - Date.now());
      render(remainingMs);
      if (remainingMs === 0) finish();
    }

    function start() {
      if (intervalId !== null || remainingMs <= 0) return;

      deadline = Date.now() + remainingMs;
      startButton.disabled = true;
      pauseButton.disabled = false;
      status.textContent = "Відлік триває.";
      intervalId = setInterval(update, 200);
      update();
    }

    function pause() {
      if (intervalId === null) return;

      // Уточнюємо залишок саме в момент натискання.
      update();
      if (remainingMs === 0) return;

      stopUpdates();
      startButton.disabled = false;
      status.textContent = "Відлік призупинено.";
    }

    function reset() {
      stopUpdates();
      remainingMs = INITIAL_MS;
      deadline = 0;
      render(remainingMs);
      startButton.disabled = false;
      timer.classList.remove("is-finished");
      status.textContent = "Готово до запуску.";
    }

    startButton.addEventListener("click", start);
    pauseButton.addEventListener("click", pause);
    resetButton.addEventListener("click", reset);

    document.addEventListener("visibilitychange", () => {
      if (!document.hidden && intervalId !== null) update();
    });

    render(remainingMs);
  </script>
</body>
</html>
```

### 6.3. Розбір обчислень

Перетворення мілісекунд у хвилини й секунди складається з трьох дій. Спочатку ділимо залишок на 1000 та округлюємо вгору, потім знаходимо цілу кількість хвилин і остачу секунд. Наприклад, для 65 200 мс отримаємо 66 секунд, тобто `01:06`.

`Math.ceil()` дозволяє показувати `00:01`, поки залишок додатний і менший за секунду. Інакше `Math.floor()` показав би `00:00` ще до фактичного завершення. Сам факт завершення перевіряємо за мілісекундами, а не за текстом на екрані.

Інтервал 200 мс потрібний для оновлення відображення. Він не визначає швидкість плину часу. Частіше оновлення може зменшити видиме запізнення зміни цифри в активній вкладці, але не дає гарантії точного моменту спрацювання.

Функція `pause()` викликає `update()` перед зупинкою: між останнім перемальовуванням і натисканням уже міг минути додатковий час. Якщо термін саме сплив, `update()` виконає `finish()`, і компонент залишиться завершеним.

Окремий елемент `role="status"` повідомляє про запуск, паузу та завершення. Цифри мають `aria-live="off"`, щоб допоміжні технології не оголошували відлік щосекунди. Для користувача важливі керування та подія завершення.

### 6.4. Що відбувається на паузі й після перезавантаження

Нехай під час паузи залишилося 24 500 мс. Після десяти секунд очікування натискаємо «Старт». Новий `deadline` дорівнюватиме поточному часу плюс 24 500 мс: час на паузі до вправи не зараховується.

Перехід у фонову вкладку не є натисканням «Пауза». Кінцевий термін залишається тим самим. Повернувшись на сторінку, користувач побачить актуальний залишок або завершений відлік.

Після перезавантаження цей приклад починає роботу заново. Як продовження попередньої лекції про Web Storage можна зберігати кінцеву позначку для запущеного стану, а для паузи — окремо залишок і ознаку паузи. Зберігати лише ID інтервалу немає сенсу: він не відновлює таймер у новому документі.

## 7. Практичний приклад: слайдер на чистому JavaScript

### 7.1. Модель слайдера

Слайдер — компонент, який показує один елемент із набору. Основний стан — індекс активного слайда. Якщо слайдів три, допустимі індекси — `0`, `1`, `2`. Перехід уперед із `2` має повернути нас до `0`, а назад із `0` — до `2`.

Для переходів на один крок використаємо:

```javascript
index = (index + step + slides.length) % slides.length;
```

Додавання довжини дозволяє уникнути від'ємного результату для кроку `-1`. У JavaScript `%` є оператором остачі, тому `-1 % 3` дає `-1`. Для довільних, зокрема великих від'ємних індексів, загальніша нормалізація має вигляд `((value % length) + length) % length`.

Відокремимо дві речі: **намір користувача** ввімкнути автоматичний показ і **наявність активного інтервалу**. Автопоказ може залишатися ввімкненим у налаштуванні, але тимчасово не працювати через приховану вкладку або взаємодію зі слайдером.

### 7.2. Повний приклад

Збережіть код у файл `slider.html`. Для відтворюваності використаємо текстові картки: приклад працює без завантаження зображень. Згодом у кожну картку можна додати власне зображення з доречним `alt`.

```html
<!doctype html>
<html lang="uk">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Навчальний слайдер</title>
  <style>
    body { font-family: system-ui, sans-serif; padding: 2rem; }
    .slider { max-width: 36rem; margin: auto; }
    .slide { padding: 2rem; border: 2px solid #345; border-radius: 1rem; }
    .slide:nth-child(1) { background: #eef6ff; }
    .slide:nth-child(2) { background: #efffee; }
    .slide:nth-child(3) { background: #fff6e8; }
    button { padding: 0.6rem; margin: 0.2rem; }
    button:focus-visible { outline: 3px solid #174ea6; outline-offset: 3px; }
  </style>
</head>
<body>
  <section id="slider" class="slider" aria-labelledby="slider-title">
    <h1 id="slider-title">Три кроки роботи з таймерами</h1>
    <div id="slides">
      <article class="slide">
        <h2>1. Заплануйте дію</h2>
        <p>Передайте функцію та потрібну затримку.</p>
      </article>
      <article class="slide" hidden>
        <h2>2. Збережіть ідентифікатор</h2>
        <p>Він потрібний для керованої зупинки.</p>
      </article>
      <article class="slide" hidden>
        <h2>3. Перевірте стан</h2>
        <p>Уникайте повторного запуску того самого інтервалу.</p>
      </article>
    </div>

    <div>
      <button id="prev" type="button" aria-controls="slides">Назад</button>
      <button id="next" type="button" aria-controls="slides">Далі</button>
      <button id="auto" type="button" aria-pressed="false">Автопоказ</button>
    </div>
    <p id="slide-position" role="status">Слайд 1 з 3</p>
    <p>Автопоказ призупиняється під час наведення. Після взаємодії
      з клавіатури або ручного перемикання його треба ввімкнути знову.</p>
  </section>

  <script>
    const slider = document.querySelector("#slider");
    const slides = [...slider.querySelectorAll(".slide")];
    const prevButton = document.querySelector("#prev");
    const nextButton = document.querySelector("#next");
    const autoButton = document.querySelector("#auto");
    const position = document.querySelector("#slide-position");
    const motionPreference = matchMedia("(prefers-reduced-motion: reduce)");

    let index = 0;
    let autoEnabled = false;
    let intervalId = null;
    let hovered = false;

    function render() {
      slides.forEach((slide, slideIndex) => {
        slide.hidden = slideIndex !== index;
      });
      position.textContent = `Слайд ${index + 1} з ${slides.length}`;
    }

    function move(step) {
      index = (index + step + slides.length) % slides.length;
      render();
    }

    function stopInterval() {
      clearInterval(intervalId);
      intervalId = null;
    }

    function syncAutoplay() {
      stopInterval();
      autoButton.setAttribute("aria-pressed", String(autoEnabled));

      const canPlay = autoEnabled && !hovered && !document.hidden;
      // Під час автоматичних змін не оголошуємо кожну картку.
      position.setAttribute("aria-live", canPlay ? "off" : "polite");

      if (canPlay) {
        intervalId = setInterval(() => move(1), 4000);
      }
    }

    function disableAutoplay() {
      autoEnabled = false;
      syncAutoplay();
    }

    function manualMove(step) {
      disableAutoplay();
      move(step);
    }

    prevButton.addEventListener("click", () => manualMove(-1));
    nextButton.addEventListener("click", () => manualMove(1));

    autoButton.addEventListener("click", () => {
      autoEnabled = !autoEnabled;
      syncAutoplay();
    });

    slider.addEventListener("mouseenter", () => {
      hovered = true;
      syncAutoplay();
    });

    slider.addEventListener("mouseleave", () => {
      hovered = false;
      syncAutoplay();
    });

    slider.addEventListener("focusin", disableAutoplay);

    // Також зупиняємо показ, якщо фокус уже був усередині секції.
    slider.addEventListener("keydown", (event) => {
      if (event.key === "Tab") disableAutoplay();
    });

    document.addEventListener("visibilitychange", syncAutoplay);

    motionPreference.addEventListener("change", (event) => {
      if (event.matches) disableAutoplay();
    });

    render();
    syncAutoplay();
  </script>
</body>
</html>
```

### 7.3. Як працює керування

`render()` залишає видимою лише активну картку. Властивість `hidden` одночасно прибирає неактивні елементи з відображення та звичайного представлення допоміжним технологіям. Кнопки є справжніми елементами `button`, тому підтримують стандартне керування клавіатурою без додаткової імітації натискань.

`manualMove()` вимикає автопоказ і змінює індекс. Це дає користувачеві час читати вибрану картку. Кнопка «Автопоказ» працює як перемикач: `aria-pressed` відображає його ввімкнений стан. Автоматичний запуск при завантаженні не виконується; користувач вмикає його сам.

`syncAutoplay()` завжди спочатку прибирає попередній інтервал, потім вирішує, чи створювати новий. Тому наведення, повернення вкладки й натискання кнопки не накопичують паралельних інтервалів. Після зняття наведення або повернення видимості починається новий чотирисекундний період.

Подія `focusin` вимикає показ, коли фокус переходить до елементів слайдера. Якщо користувач свідомо натисне «Автопоказ», він знову ввімкнеться; наступний перехід фокусу або ручна дія його зупинить. Для вже сфокусованої кнопки окремо враховано натискання Tab. Жоден автоматичний перехід не переміщує фокус.

Слайдер змінює картки миттєво; він не використовує покадрову анімацію. Якщо користувач увімкне системне налаштування зменшення руху під час роботи, автопоказ зупиниться. За потреби користувач може знову явно ввімкнути його кнопкою.

Приклад розрахований на наявні три картки. Для компонента, що отримує дані динамічно, додатково перевіряють порожній набір і випадок єдиного слайда: за відсутності переходів кнопки та автопоказ мають бути вимкнені.

### 7.4. Автопоказ і візуальний перехід — різні механізми

Інтервал у 4000 мс визначає, **коли вибрати наступну картку**. Можливий CSS-перехід на 300 мс визначав би, **як показати зміну**. Ці тривалості не треба змішувати. Додавання анімації потребувало б окремого керування початковим і кінцевим станом та доступністю слайдів під час переходу.

Не слід встановлювати `display: none` на елемент і чекати, що звичайний перехід `opacity` автоматично відтвориться: прихований елемент не відображає проміжні стани. Для базового навчального слайдера миттєве перемикання через `hidden` робить логіку зрозумілішою.

## 8. Типові помилки, перевірка та практичні завдання

### 8.1. Поширені помилки

| Помилка | Наслідок | Як виправити |
| --- | --- | --- |
| `setTimeout(action(), 1000)` | Дія виконується під час реєстрації | Передати `action` або `() => action()` |
| Затримка `5` замість `5000` | Очікування становить мілісекунди | Указувати одиниці у назвах: `delayMs` |
| Кожен «Старт» створює інтервал | Оновлення множаться | Перевіряти збережений ID |
| Присвоєно `id = null` без скасування | Старий таймер працює далі | Спочатку викликати відповідний `clear...()` |
| Інтервал скасовано, але ID не скинуто | Перевірка стану забороняє новий запуск | Після скасування присвоїти `null` |
| Залишок зменшується на одиницю за виклик | Затримки накопичують похибку | Обчислювати різницю часових позначок |
| Відлік не зупиняється на нулі | З'являються від'ємні значення або зайві оновлення | Обмежити залишок і скасувати інтервал |
| `setInterval()` запускає запити без очікування | Запити можуть тривати одночасно | Планувати наступний після завершення попереднього |
| Примусове очікування в `while` | Інтерфейс перестає реагувати | Використати відкладене виконання |
| Автопоказ неможливо зупинити | Користувач не встигає читати | Додати керування й обробку взаємодії |

### 8.2. Життєвий цикл компонента

Таймер має існувати рівно стільки, скільки потрібна запланована дія. Якщо компонент видаляється зі сторінки без перезавантаження, його інтервали та відкладені виклики потрібно скасувати. Видалення DOM-вузла саме собою не є викликом `clearInterval()`.

У повних прикладах компоненти існують протягом життя сторінки. Для компонента, який створюють і видаляють динамічно, слід передбачити метод очищення: він скасовує таймери та прибирає зареєстровані обробники подій. Особливо це стосується обробників на `document`, які можуть залишатися після видалення конкретної секції.

### 8.3. Перевірка роботи у браузері

Перевіряти потрібно переходи між станами, а не лише успішний перший запуск.

Для відліку:

1. Відкрийте `countdown.html`: показано `01:00`, кнопка паузи недоступна.
2. Запустіть відлік і кілька разів спробуйте повторно його запустити. Швидкість не має змінитися.
3. Натисніть «Пауза», зачекайте, продовжте. Час на паузі не має зараховуватися.
4. Натисніть «Скинути» під час відліку. Значення має повернутися до `01:00` й залишатися незмінним.
5. Для швидкої перевірки змініть `INITIAL_MS` на `3000`. Після завершення очікуйте `00:00`, повідомлення й відсутність подальших оновлень.
6. Запустіть відлік і перейдіть на іншу вкладку довше за його тривалість. Після повернення очікуйте завершений стан.

Для слайдера:

1. Відкрийте `slider.html`: без натискання «Автопоказ» картка сама не змінюється.
2. Перейдіть назад із першої картки й уперед з останньої. Перевірте циклічність і номер слайда.
3. Увімкніть автопоказ, наведіть вказівник на секцію, зачекайте понад чотири секунди. Переходів під час наведення бути не повинно.
4. Відведіть вказівник за межі секції. Після нового періоду показ має продовжитися.
5. Під час автопоказу перейдіть до кнопок клавішею Tab або вручну виберіть іншу картку. Автопоказ має вимкнутися.
6. Увімкніть автопоказ, переведіть вказівник за межі секції й приховайте вкладку. Після повернення новий інтервал має початися без серії швидких «наздоганяючих» переходів.

У консолі DevTools перевірте відсутність помилок. Під час перевірки наведення враховуйте положення вказівника: якщо він залишається над слайдером після натискання «Автопоказ», показ перебуває на тимчасовій паузі відповідно до заданої поведінки.

### 8.4. Завдання для самостійної роботи

**Завдання 1. Нагадування.** Створіть дві кнопки: «Нагадати через 5 секунд» і «Скасувати». Повторне замовлення нагадування має замінювати попереднє. Критерій перевірки: після кількох натискань з'являється лише одне актуальне повідомлення.

**Завдання 2. Налаштовуваний відлік.** Додайте до прикладу поле введення кількості секунд. Дозволяйте лише цілі значення від 1 до 3600 й застосовуйте нову тривалість у зупиненому стані. Критерій перевірки: порожнє поле, нуль, від'ємне та дробове значення не запускають некоректний таймер.

**Завдання 3. Слайдер із зображеннями.** Замініть текстові картки власними зображеннями з підписами. Збережіть кнопки, циклічність і можливість зупинити автопоказ. Критерій перевірки: неактивні слайди приховані, зображення мають змістовний `alt`, керування доступне з клавіатури.

**Завдання 4. Відкладене опрацювання введення.** Для текстового поля заплануйте виведення його значення в консоль через 500 мс після останньої події `input`. Кожне нове введення має скасовувати попередній таймер. Такий прийом називають *debounce*: дія виконується після паузи в потоці подій. Критерій перевірки: швидке введення слова спричиняє одне опрацювання після зупинки набору.

**Завдання 5. Відновлення стану.** Використайте знання попередньої лекції про Web Storage: збережіть стан відліку так, щоб після перезавантаження запущений таймер ураховував час, який минув, а призупинений залишався на паузі. Критерій перевірки: збережено дані стану та часову позначку, а не ID браузерного інтервалу.

## Висновки

`setTimeout()` планує одноразову дію, а `setInterval()` — повторювані виклики. Їхні ідентифікатори потрібні для керованої зупинки. Збереження ID, перевірка перед запуском і скидання стану після скасування запобігають більшості помилок із кількома одночасними таймерами.

Виклики таймерів можуть запізнюватися, тому вимірювання часу слід відокремлювати від частоти оновлення інтерфейсу. Таймер зворотного відліку обчислює залишок за часовими позначками; інтервал лише дає привід оновити екран. Пауза, завершення та скидання є окремими переходами стану.

Для простих візуальних переходів зручно поєднувати зміну CSS-класів із `transition`. Для покадрових обчислень використовують `requestAnimationFrame()`. Слайдер поєднує індекс активного елемента, відображення DOM і правила автоматичного запуску. У кожному компоненті керування часом має узгоджуватися з діями користувача, видимістю сторінки й можливістю зупинити автоматичні зміни.
